# Пометки по интерфейсам и UX-референсам Event Gallery

Дата: 2026-05-18

Файл фиксирует выводы после изучения сохраненных страниц Partiful и описания будущей логики Event Gallery. Это не задание на копирование Partiful. Референсы используются только как ориентир по сценариям, структуре экранов и плотности интерфейса.

## Ограничения

- Не копировать бренд, тексты, изображения, логотипы и конкретный визуальный стиль Partiful.
- Использовать сохраненные страницы только как UX-референс.
- Не использовать внешние изображения из интернета.
- Не подключать API изображений.
- Не добавлять тяжелые библиотеки анимаций.
- Анимации допустимы только легкие: CSS hover, появление, мягкое движение декоративных элементов.
- Важный контент всегда выше декоративного слоя: кнопки, формы, текст, статусы, меню и действия не должны перекрываться картинками или анимацией.

## Изученные локальные референсы

Папка: `приеры страниц partiful`.

Основные состояния:

- `main` - публичная главная страница.
- `create_event` - экран создания события без авторизованного контекста.
- `authorixed_versions/welcome` - домашняя страница авторизованного пользователя.
- `authorixed_versions/profile` - профиль пользователя.
- `authorixed_versions/create` - создание события в авторизованном состоянии.
- `authorixed_versions/created_event` - страница созданного события в роли организатора.
- `authorixed_versions/created_event_with_gouest` - страница события с гостем/активностью.
- `authorixed_versions/переход_по_ссылке_с_другого_акка` - переход по ссылке приглашения другим аккаунтом.

## Что полезно взять из референсов

### Главная страница

Полезна сама логика:

- простая верхняя навигация;
- крупный первый экран;
- заметная кнопка создания события;
- карточки и декоративные элементы;
- легкое ощущение праздника;
- объяснение ключевых возможностей.

Для нашего проекта главная должна быть короче и спокойнее. Не нужен длинный маркетинговый лендинг с большим количеством отзывов, шаблонов и внешних блоков.

### Home пользователя

Нужен отдельный экран после входа:

- список текущих, будущих и прошедших событий;
- быстрый переход к конкретному событию;
- кнопка создания нового события;
- пустые состояния, если событий нет;
- компактный доступ к профилю и личной галерее.

Для Event Gallery вкладки лучше адаптировать так:

- `Текущие`;
- `Будущие`;
- `Прошедшие`;
- `Организую`;
- `Сохраненные`.

### Создание и редактирование события

В референсах полезны блоки:

- название события;
- дата и время;
- организатор и соорганизаторы;
- место;
- вместимость;
- стоимость с человека;
- ссылки: плейлист, дресс-код, список подарков, произвольная ссылка;
- описание;
- обложка;
- тема;
- настройки RSVP;
- дополнительные настройки.

Для MVP нужно упростить:

- название;
- дата и время;
- описание;
- место;
- обложка или CSS-тема;
- ссылка/QR;
- RSVP-статусы;
- фотоальбом;
- достижения;
- простые дополнительные ссылки.

Редактирование события можно сделать тем же экраном, что и создание, но с заполненными текущими данными.

### Страница события

Нужные блоки:

- обложка/фон события;
- название;
- дата и место;
- организатор;
- описание;
- статус участия;
- список гостей;
- общий альбом события;
- активность/чат;
- панель организатора.

Статусы участия:

- `Пойду`;
- `Возможно пойду`;
- `Не смогу пойти`.

Организатор должен иметь возможность:

- редактировать событие;
- приглашать людей;
- менять статус гостей;
- удалять гостей;
- отправлять объявление всем или выбранным участникам;
- включать/отключать напоминания;
- фильтровать получателей напоминаний и объявлений;
- удалять или отменять событие.

### Чат и активность

В референсах активность совмещает комментарии, обновления и фото. Для нашего проекта логично сделать:

- общий чат события;
- системные сообщения: кто загрузил фото, кто получил достижение, кто изменил статус;
- объявления организатора;
- отправку текста;
- отправку фото;
- позже можно добавить GIF.

Фото из чата должны автоматически попадать в общий альбом события.

### Альбом события

Нужно уйти от простой логики "общий фотоальбом и все". В Event Gallery альбом должен стать центральной частью проекта.

Структура:

- у события есть общий альбом;
- участники загружают фото в общий альбом;
- фото можно лайкать;
- фото можно скачать;
- пользователь может сохранить выбранные фото в личную галерею;
- сохраненные фото привязываются к карточке конкретного события в личной галерее.

### Личная галерея

Идея личной галереи:

- выглядит как обычная галерея телефона;
- фото идут последовательно;
- фото сгруппированы визуальными карточками событий;
- каждая карточка события имеет собственный фон/тему/обложку;
- внутри карточки отображаются сохраненные фото с этого события;
- сверху или рядом с карточкой показываются маленькие медали достижений;
- пользователь может вернуться на страницу события и добавить новые фото в ту же карточку.

Это важное отличие проекта от обычных облачных папок и от референса.

### Достижения и геймификация

Достижения нужны не как декор, а как доказуемый элемент геймификации для диплома.

Группы достижений:

1. Личные достижения.
   - Выдаются конкретному участнику.
   - Обычно вручную организатором.
   - Примеры для диплома должны быть нейтральными: `Помощник организатора`, `Лучший кадр`, `Душа события`.

2. Автоматические достижения.
   - Выдаются системой по правилам.
   - Можно включать или отключать при создании события.
   - Примеры: `Первое фото`, `Больше всех фото`, `Самое популярное фото`, `Первый лайк`.

3. Общие достижения события.
   - Относятся ко всей группе.
   - Показывают общий прогресс события.
   - Примеры: `Собрали 50 фото`, `Все участники отметились`, `Групповое фото загружено`.

Визуально личные/автоматические достижения и общие достижения события лучше разделять:

- личные и автоматические - маленькие медали на карточке пользователя или фото;
- общие - отдельная плашка прогресса события.

Создание достижений:

- название;
- описание;
- тип: личное, автоматическое, общее;
- иконка из набора;
- возможность загрузить свою картинку позже;
- правило автоматической выдачи, если тип автоматический;
- ручное назначение участникам, если тип личный.

### Рейтинг и очки

Чтобы комиссия видела геймификацию, можно добавить простую систему:

- очки за загрузку фото;
- очки за лайки;
- очки за получение достижений;
- рейтинг участников внутри события;
- блок достижений в личном кабинете;
- общий счетчик активности события.

Не нужно делать сложную экономику баллов. Достаточно понятной и объяснимой логики.

### Дополнительные возможности

Можно добавить как второстепенные или перспективные:

- плейлист;
- дресс-код;
- произвольные ссылки;
- стоимость участия;
- отметка "скинул/не скинул";
- статистика оплат для организатора;
- вместимость и лист ожидания;
- ограничение +1;
- скрытие списка гостей;
- приватность места до подтверждения участия;
- напоминания.

Для MVP лучше не перегружать первый этап оплатами, сложными напоминаниями и GIF.

## Предлагаемая карта экранов

1. `Landing / вход`.
   - Уже есть первый прототип.
   - Дальше можно связать с гостевым входом и профилем.

2. `Home`.
   - События пользователя.
   - Вкладки текущих, будущих, прошедших и организуемых событий.
   - Кнопка создания события.

3. `Create Event / Edit Event`.
   - Единая форма создания и редактирования.
   - Обложка, фон, тема.
   - Основная информация.
   - RSVP.
   - Достижения.
   - Дополнительные ссылки.

4. `Event Page`.
   - Главная страница конкретного события.
   - RSVP-статусы.
   - Гости.
   - Панель организатора.
   - Альбом.
   - Чат/активность.

5. `Event Album`.
   - Общий альбом события.
   - Загрузка фото.
   - Лайки.
   - Сохранение в личную галерею.

6. `Personal Gallery`.
   - Последовательная галерея фото.
   - Группировка по визуальным карточкам событий.
   - Маленькие достижения/медали на карточках.

7. `Achievements`.
   - Библиотека достижений события.
   - Создание кастомного достижения.
   - Ручная выдача участникам.
   - Автоматические правила.

8. `Profile`.
   - Имя, аватар, контакты.
   - Статистика.
   - Личные достижения.
   - История событий.

## Приоритет MVP

Для ближайшей разработки достаточно:

1. Home с событиями.
2. Создание события.
3. Страница события.
4. RSVP-статусы.
5. Общий альбом.
6. Личная галерея.
7. Базовые достижения.
8. Простая панель организатора.

Можно отложить:

- сложные напоминания;
- GIF;
- оплату;
- расширенную модерацию;
- OAuth;
- полноценную систему приглашений;
- публичную афишу;
- сложные анимации;
- экспорт всех фото архивом.

## Чего пока не хватает

Для продолжения интерфейсного проектирования текущего контекста достаточно.

Для следующего этапа желательно уточнить:

1. Какие экраны делаем первыми: Home, Event Page или Create Event.
2. Должен ли следующий прототип быть на mock-данных или сразу со структурой сервисов.
3. Включаем ли оплату/скидывание денег в MVP или оставляем в перспективах.
4. Сколько достижений нужно показать в демо: минимально 6-8 будет достаточно.
5. Нужна ли отдельная страница личной галереи уже сейчас или сначала только блок-превью.

## Важная UI-пометка

Декоративные изображения, плавающие карточки, стикеры и анимации должны иметь низкий визуальный приоритет. Для реализации:

- декоративный слой держать с меньшим `z-index`;
- смысловой текст, кнопки и формы держать выше;
- на мобильных экранах часть декора скрывать или уменьшать;
- не размещать анимированные элементы поверх CTA-кнопок, статусов RSVP, формы входа, чата и меню организатора.
