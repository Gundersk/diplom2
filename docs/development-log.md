## 2026-05-17. Шаг 1: старт frontend-прототипа главного окна

### Цель

Создать первый рабочий frontend-прототип главной страницы дипломного проекта Event Gallery. Интерфейс должен использовать Partiful только как UX-референс: простая главная, крупный hero-блок, заметная кнопка создания события, карточки и легкое праздничное настроение.

Важно: бренд, тексты, изображения, логотипы, конкретные стили и исходный код Partiful не копировались. Внешние изображения и API изображений не использовались.

### Что было изучено

В папке `приеры страниц partiful/main` лежит сохраненная главная страница Partiful. Она оказалась экспортом Framer с большим количеством автогенерированного CSS, JS и внешних ссылок. Поэтому ее код не переносился в проект.

Из референса взята только общая UX-логика:

- верхняя навигация;
- крупный первый экран;
- основная кнопка создания события;
- визуальные карточки события;
- ощущение простоты и праздника;
- легкая динамика без сложных анимаций.

### Архитектурное решение

Для frontend выбран стек из концепции диплома:

- Vue 3 для компонентного интерфейса;
- Vite для dev-сервера и сборки;
- TypeScript для типизации;
- CSS без внешних изображений и тяжелых animation-библиотек.

На этом шаге Tailwind CSS пока не подключался, чтобы быстрее получить понятный первый прототип и не усложнять стартовую структуру. Его можно добавить позже, если будет удобнее развивать дизайн через utility-классы.

### Созданные файлы

- `package.json` - описание npm-проекта, зависимости и команды запуска.
- `package-lock.json` - зафиксированные версии npm-зависимостей.
- `index.html` - HTML-точка входа Vite-приложения.
- `vite.config.ts` - конфигурация Vite с Vue-плагином.
- `tsconfig.json` - настройки TypeScript.
- `src/main.ts` - создание Vue-приложения и подключение стилей.
- `src/App.vue` - главный экран, переключение тем и модальное окно входа.
- `src/style.css` - вся визуальная система первого прототипа.
- `src/env.d.ts` - типы Vite.
- `.gitignore` - исключение `node_modules`, `dist` и служебных файлов.

### Что реализовано

Главная страница содержит:

- бренд `Event Gallery`;
- верхнюю навигацию;
- hero-блок с описанием проекта;
- кнопку `Создать событие`;
- кнопку `Войти по коду`;
- декоративную карточку события;
- mock QR-блок;
- mock-photo карточки без внешних изображений;
- блок основного сценария: создать событие, пригласить гостей, собрать фото;
- блок кастомности события;
- переключение тем: `Вечер`, `Студенты`, `Квест`;
- блок ключевых возможностей MVP;
- модальное окно авторизации;
- два режима входа: гостевой вход и вход в профиль.

### Почему так сделано

Для дипломного MVP важно показать идею быстро и надежно:

- главный экран сразу объясняет назначение системы;
- кнопка создания события видна в первом экране;
- гостевой вход снижает сложность авторизации;
- темы события демонстрируют кастомность без сложного редактора;
- mock-photo и CSS-градиенты заменяют реальные изображения до подключения хранилища;
- визуальные бейджи и очки заранее готовят основу для геймификации.

### Как повторить вручную

1. Создать npm-проект в корне репозитория:

```bash
npm init -y
```

2. Установить зависимости:

```bash
npm install vue
npm install -D vite @vitejs/plugin-vue typescript vue-tsc
```

3. Создать `index.html`, `vite.config.ts`, `tsconfig.json`.

4. Создать папку `src` и файлы `main.ts`, `App.vue`, `style.css`, `env.d.ts`.

5. В `main.ts` подключить Vue-приложение:

```ts
import { createApp } from 'vue'
import App from './App.vue'
import './style.css'

createApp(App).mount('#app')
```

6. В `App.vue` описать состояние:

- выбранная тема события;
- открыто ли окно авторизации;
- режим входа: гость или профиль.

7. В CSS настроить:

- адаптивную сетку;
- hero-блок;
- карточки;
- кнопки;
- модальное окно;
- media queries для мобильного экрана.

8. Проверить проект:

```bash
npm run build
npm run dev -- --port 5173
```

Выполнена production-сборка:

```bash

```

Результат: сборка прошла успешно, Vite собрал проект без ошибок.

Страница также была визуально проверена в браузере:

После мобильной проверки был уменьшен hero-заголовок и поправлено расположение декоративных карточек, чтобы текст не выходил за экран.

## 2026-05-17. Шаг 2: выравнивание карточки кастомности

### Цель

Исправить визуальную проблему в блоке кастомности события. Карточка-превью, где отображается выбранная тема (`Вечер`, `Студенты`, `Квест`), была слегка повернута через CSS. На большом экране это выглядело как декоративный прием, но на маленьких экранах карточка занимала почти всю ширину и наклон становился похож на ошибку верстки.

### Что изменено

```css

```

```gitignore
.codex_*
vite_stdout.log
vite_stderr.log
```

### Почему так сделано

Для дипломного интерфейса лучше, чтобы основные контейнеры были визуально ровными и предсказуемыми. Декоративный наклон можно оставлять у небольших mock-карточек в hero-блоке, но не у крупного контейнера, который на мобильном становится основной рабочей областью.

### Как повторить вручную

1. Открыть `src/style.css`.
2. Найти класс `.studio-preview`.
3. Удалить строку `transform: rotate(1deg);`.


5. Открыть страницу на маленькой ширине экрана и проверить, что карточка стоит ровно.

## 2026-05-18. Шаг 4: уточнение Home, гибридной галереи, оплаты и достижений

### Цель

Зафиксировать более точные продуктовые решения после обсуждения Home-экрана, личной галереи, альбомов, оплаты и достижений. На этом шаге код приложения не менялся: задача была в том, чтобы перед следующей реализацией не потерять логику интерфейса.

### Что уточнено

- После авторизации пользователь попадает на Home-экран.
- Home объединяет список событий и личную галерею.
- В MVP все события приватные и доступны по ссылке или QR.
- Организатор может разрешить или запретить гостям приглашать других людей.
- Профиль нужен в минимальном виде: имя, аватар, выход.
- Уведомления нужны для объявлений, ответов в чате, новых фото и достижений.
- Личная галерея работает как гибрид: карточки событий раскрываются до фото.
- Кнопка `Раскрыть все фото` переводит Home в режим фотоленты, но сохраняет группировку по событиям.
- При просмотре отдельного фото фон должен соответствовать событию.
- Реальных оплат внутри приложения нет: только сумма, инструкция и ручные отметки `Оплатил` / `Оплачу позже`.
- Достижения упрощены: автоматические личные медальки, кастомные личные и кастомные групповые.

### Созданные файлы

- `docs/home-gallery-product-decisions.md` - подробные решения по Home, галерее, оплате и достижениям.
- `docs/manual-context-log.md` - короткое сжатие пользовательского контекста, чтобы не терять важные решения между этапами.

### Почему так сделано

Перед реализацией Home важно было определить, что именно является центральным экраном после входа. Решение: не делать отдельную тяжелую галерею по примеру HTML-макета, а встроить ее в Home через карточки событий. Это проще для MVP, лучше объясняется на защите и сильнее поддерживает основную идею проекта: фото хранятся не просто сеткой, а как воспоминания, привязанные к событиям.

### Следующий технический шаг

Следующим крупным экраном логично делать Home на mock-данных:

1. верхняя панель;
2. профиль и уведомления;
3. кнопка создания события;
4. вкладки событий;
5. карточки событий;
6. раскрытие карточки до фото;
7. режим `Раскрыть все фото`.

## 2026-05-18. Шаг 5: реализация Home-экрана на mock-данных

### Цель

Сделать первый рабочий вариант экрана после авторизации. Home должен объединять события и личную галерею: пользователь видит карточки мероприятий, может раскрыть событие до сохраненных фото, открыть фото в просмотрщике и перейти к следующему снимку с изменением фона под событие.

### Что изменено в интерфейсе

- После отправки формы авторизации приложение переключается с главной страницы на Home.
- Добавлена верхняя панель личного кабинета: логотип, уведомления, кнопка создания события и профиль.
- В меню профиля есть базовые действия: изменить имя, изменить аватар, выйти.
- Уведомления показываются отдельной плашкой с объявлениями, достижениями и ответами в чате.
- Добавлен hero-блок Home со статистикой: количество событий, сохраненных фото и медалей.
- Добавлены вкладки событий: текущие, будущие, прошедшие, организую.
- События отображаются карточками с CSS-градиентной обложкой, ролью пользователя, политикой приглашений, оплатой как визуальной отметкой и медальками.
- Карточку события можно раскрыть до сохраненных фото.
- Кнопка `Раскрыть все фото` включает режим фотоленты внутри карточек событий.
- Просмотрщик фото открывается поверх интерфейса; при переходе дальше фон меняется на фон события, которому принадлежит следующая фотография.

### Что изменено в коде

- В `src/App.vue` добавлены типы и mock-данные для событий, фотографий и уведомлений.
- В `src/App.vue` добавлено состояние Home: текущая вкладка, раскрытые события, режим всех фото, выбранное фото, меню профиля и уведомлений.
- В `src/App.vue` добавлены функции переключения Home-состояний: вход, выход, раскрытие события, раскрытие всех фото, открытие фото и переход между фото.
- В `src/style.css` добавлен отдельный слой стилей для Home: адаптивная сетка, карточки событий, медальки, mock-photo плитки, боковая панель, попапы и просмотрщик фото.

### Почему так сделано

Home выбран как центральный экран MVP. Отдельную тяжелую страницу галереи пока не делаем: события и фотографии живут вместе, поэтому пользователю проще понять связь `мероприятие -> общий альбом -> мои сохраненные фото`. Для диплома это также проще объяснить: экран демонстрирует личный кабинет, геймификацию, альбомы, приватные события и базовую навигацию без настоящего backend.

Дизайн не копирует Partiful. Взята только UX-идея: простая домашняя страница, крупные карточки событий, праздничный характер, быстрый вход в создание события и легкая кастомность. Все изображения заменены CSS-градиентами и декоративными mock-photo блоками.

1. В `src/App.vue` добавить состояние текущего экрана: `landing` или `home`.

9. В CSS описать адаптивную сетку: на desktop две колонки, на mobile одна колонка.
10. Запустить `npm run build` и проверить страницу в браузере.

## 2026-05-18. Шаг 6: переработка Home под плиточную ленту событий

### Цель

Исправить Home после визуального ревью. Первый вариант был слишком похож на информационный dashboard: крупный вводный блок, статистика и справочные панели занимали много места, а в текущей вкладке отображалось только одно событие. Нужно было сделать экран ближе к ожидаемой логике: сначала лента событий плитками, затем раскрытие конкретного события в полноширинную галерею.

### Что изменено

- Удален вводный hero-блок Home со статистикой.
- Удалены боковые справочные панели `Автоматические медали` и `Событийный контекст`.
- Вкладка `Организую` убрана: роль пользователя теперь показывается бейджем прямо на карточке события.
- В Home добавлены несколько событий для каждого статуса: текущие, будущие и прошедшие.
- События сортируются по `sortOrder`, то есть в интерфейсе идут в заданном хронологическом порядке.
- В свернутом состоянии событие выглядит как квадратная карточка с фоном события, названием, датой, ролью пользователя и организатором.
- В раскрытом состоянии событие занимает всю ширину ленты.
- Внутри раскрытого события фотографии отображаются как обычная галерея без текстовых подписей на самих фото.
- Достижения события вынесены наверх раскрытого блока и визуально частично выходят за его границу.
- При клике на достижение появляется пояснение, за что оно выдается.
- Кнопка `Раскрыть все события` раскрывает все события текущей вкладки; если все уже раскрыты, она сворачивает их обратно.

### Почему так сделано

Home должен быть рабочим экраном, а не презентационной страницей. Пользователь заходит после авторизации и сразу видит свои мероприятия. Справочную информацию лучше оставить для документации и защиты, а не держать в интерфейсе. Роль организатора или участника важна, но она должна быть компактной частью карточки, а настройки приглашений и оплаты относятся к странице конкретного события или редактированию события.

### Как повторить вручную

1. В данных события оставить только поля, нужные для Home: статус, порядок, роль, организатор, обложка, достижения и фотографии.
2. Убрать отдельную вкладку `Организую`.
3. Сделать вычисляемый список `visibleEvents`, который фильтрует события по текущей вкладке и сортирует их по порядку.
4. Для свернутого события сверстать квадратную кнопку-карточку.
5. Для раскрытого события использовать тот же объект данных, но другой шаблон: широкий блок, фон события, достижения сверху, сетка фото.
6. Хранить раскрытые события в `Set` по id.
7. Для кнопки `Раскрыть все события` добавлять или удалять из `Set` все события текущей вкладки.
8. Для достижений хранить активный id и показывать небольшую плашку-описание по клику.
9. Проверить desktop и mobile: компактные события должны идти плитками, а раскрытый блок занимать всю ширину.

### Проверка

Запущено:

```bash
npm run build
```

В браузере проверено:

- по умолчанию отображается несколько текущих событий плитками;
- `Раскрыть все события` раскрывает все события активной вкладки;
- раскрытое событие занимает всю ширину контейнера;
- фото в раскрытом событии не содержат подписей;
- достижения кликабельны и показывают описание;
- на мобильной ширине события идут по две плитки в ряд;
- горизонтального переполнения нет;
- ошибок в консоли браузера нет.
