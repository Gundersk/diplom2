3. Добавлять команды для ручного повторения и проверки.

## 2026-05-17. Шаг 1: старт frontend-прототипа главного окна

### Цель

Создать первый рабочий frontend-прототип главной страницы дипломного проекта Event Gallery. Интерфейс должен использовать Partiful только как UX-референс: простая главная, крупный hero-блок, заметная кнопка создания события, карточки и легкое праздничное настроение.

Важно: бренд, тексты, изображения, логотипы, конкретные стили и исходный код Partiful не копировались. Внешние изображения и API изображений не использовались.

### Что было изучено

В папке `приеры страниц partiful/main` лежит сохраненная главная страница Partiful. Она оказалась экспортом Framer с большим количеством автогенерированного CSS, JS и внешних ссылок. Поэтому ее код не переносился в проект.

Из референса взята только общая UX-логика:

- верхняя навигация;
- крупный первый экран;
- основная кнопка создания события;
- визуальные карточки события;
- ощущение простоты и праздника;
- легкая динамика без сложных анимаций.

### Архитектурное решение

Для frontend выбран стек из концепции диплома:

- Vue 3 для компонентного интерфейса;
- Vite для dev-сервера и сборки;
- TypeScript для типизации;
- CSS без внешних изображений и тяжелых animation-библиотек.

На этом шаге Tailwind CSS пока не подключался, чтобы быстрее получить понятный первый прототип и не усложнять стартовую структуру. Его можно добавить позже, если будет удобнее развивать дизайн через utility-классы.

### Созданные файлы

- `package.json` - описание npm-проекта, зависимости и команды запуска.
- `package-lock.json` - зафиксированные версии npm-зависимостей.
- `index.html` - HTML-точка входа Vite-приложения.
- `vite.config.ts` - конфигурация Vite с Vue-плагином.
- `tsconfig.json` - настройки TypeScript.
- `src/main.ts` - создание Vue-приложения и подключение стилей.
- `src/App.vue` - главный экран, переключение тем и модальное окно входа.
- `src/style.css` - вся визуальная система первого прототипа.
- `src/env.d.ts` - типы Vite.
- `.gitignore` - исключение `node_modules`, `dist` и служебных файлов.

### Что реализовано

Главная страница содержит:

- бренд `Event Gallery`;
- верхнюю навигацию;
- hero-блок с описанием проекта;
- кнопку `Создать событие`;
- кнопку `Войти по коду`;
- декоративную карточку события;
- mock QR-блок;
- mock-photo карточки без внешних изображений;
- блок основного сценария: создать событие, пригласить гостей, собрать фото;
- блок кастомности события;
- переключение тем: `Вечер`, `Студенты`, `Квест`;
- блок ключевых возможностей MVP;
- модальное окно авторизации;
- два режима входа: гостевой вход и вход в профиль.

### Почему так сделано

Для дипломного MVP важно показать идею быстро и надежно:

- главный экран сразу объясняет назначение системы;
- кнопка создания события видна в первом экране;
- гостевой вход снижает сложность авторизации;
- темы события демонстрируют кастомность без сложного редактора;
- mock-photo и CSS-градиенты заменяют реальные изображения до подключения хранилища;
- визуальные бейджи и очки заранее готовят основу для геймификации.

### Как повторить вручную

1. Создать npm-проект в корне репозитория:

```bash
npm init -y
```

2. Установить зависимости:

```bash
npm install vue
npm install -D vite @vitejs/plugin-vue typescript vue-tsc
```

3. Создать `index.html`, `vite.config.ts`, `tsconfig.json`.

4. Создать папку `src` и файлы `main.ts`, `App.vue`, `style.css`, `env.d.ts`.

5. В `main.ts` подключить Vue-приложение:

```ts
import { createApp } from 'vue'
import App from './App.vue'
import './style.css'

createApp(App).mount('#app')
```

6. В `App.vue` описать состояние:

- выбранная тема события;
- открыто ли окно авторизации;
- режим входа: гость или профиль.

7. В CSS настроить:

- адаптивную сетку;
- hero-блок;
- карточки;
- кнопки;
- модальное окно;
- media queries для мобильного экрана.

8. Проверить проект:

```bash
npm run build
npm run dev -- --port 5173
```

### Проверка

Выполнена production-сборка:

```bash
npm run build
```

Результат: сборка прошла успешно, Vite собрал проект без ошибок.

Страница также была визуально проверена в браузере:

- desktop viewport 1280x720;
- mobile viewport 390x844.

После мобильной проверки был уменьшен hero-заголовок и поправлено расположение декоративных карточек, чтобы текст не выходил за экран.

### Коммит

Планируемое название коммита:

```bash

```

## 2026-05-17. Шаг 2: выравнивание карточки кастомности

### Цель

Исправить визуальную проблему в блоке кастомности события. Карточка-превью, где отображается выбранная тема (`Вечер`, `Студенты`, `Квест`), была слегка повернута через CSS. На большом экране это выглядело как декоративный прием, но на маленьких экранах карточка занимала почти всю ширину и наклон становился похож на ошибку верстки.

### Что изменено

В файле `src/style.css` у класса `.studio-preview` удалено свойство:

```css
transform: rotate(1deg);
```

Также в `.gitignore` добавлены временные файлы локального dev-сервера:

```gitignore
.codex_*
vite_stdout.log
vite_stderr.log
```

### Почему так сделано

Для дипломного интерфейса лучше, чтобы основные контейнеры были визуально ровными и предсказуемыми. Декоративный наклон можно оставлять у небольших mock-карточек в hero-блоке, но не у крупного контейнера, который на мобильном становится основной рабочей областью.

### Как повторить вручную

1. Открыть `src/style.css`.
2. Найти класс `.studio-preview`.
3. Удалить строку `transform: rotate(1deg);`.
4. Запустить проверку:

```bash
npm run build
```

5. Открыть страницу на маленькой ширине экрана и проверить, что карточка стоит ровно.

### Коммит

Планируемое название коммита:

```bash
fix: align customization preview card
```

## 2026-05-18. Шаг 3: анализ UX-референсов и будущей структуры интерфейса

### Цель

Изучить новые сохраненные страницы Partiful и описание желаемой логики Event Gallery без проектирования новых экранов в коде. Нужно было понять, достаточно ли контекста для дальнейшей работы, и зафиксировать будущие интерфейсные направления.

### Что было изучено

В папке `приеры страниц partiful` появились дополнительные референсы:

- `create_event` - создание события;
- `authorixed_versions/welcome` - домашняя страница пользователя;
- `authorixed_versions/profile` - профиль;
- `authorixed_versions/create` - создание события после входа;
- `authorixed_versions/created_event` - страница события организатора;
- `authorixed_versions/created_event_with_gouest` - событие с гостем и активностью;
- `authorixed_versions/переход_по_ссылке_с_другого_акка` - просмотр события другим аккаунтом.

Код и стили Partiful не переносились. Изучались только сценарии, блоки интерфейса и состояния.

### Что зафиксировано

Создан файл `docs/interface-reference-notes.md`. В нем записаны:

- ограничения по использованию референсов;
- полезные UX-наблюдения;
- будущая карта экранов;
- логика Home, события, альбомов, личной галереи и достижений;
- разделение достижений на личные, автоматические и общие;
- приоритеты MVP;
- список вопросов, которые желательно уточнить перед следующей реализацией.

### Почему так сделано

Референсов стало много, и держать выводы только в переписке рискованно. Для диплома полезнее иметь отдельный документ, где видно, как из анализа похожих интерфейсов появилась собственная структура проекта.

### Дополнительное решение по git

Новые скачанные страницы и ассеты Partiful не нужно коммитить: они тяжелые, содержат чужие изображения и нужны только локально как черновой референс. Поэтому в `.gitignore` добавлены:

```gitignore
приеры страниц partiful/authorixed_versions/
приеры страниц partiful/create_event/
приеры страниц partiful/create_event.zip
```

Планируемое название коммита:

